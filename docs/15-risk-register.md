# 16. Risk register

| # | Risk | Impact | Mitigation |
|---|---|---|---|
| **R1** | **On the ESP32, a crash-reboot does NOT de-energise the valve GPIOs.** `esp_restart()`, panic, and task-WDT-panic are **CPU resets**, which per the TRM leave digital GPIO output-enable *and level* intact — and **ESPHome sets `ESP_TASK_WDT_PANIC=y`**. Worse: entering `safe_mode` is itself a CPU reset, and **in safe mode the switch component never runs, so nothing ever writes the pin low**. A crash loop therefore leaves a valve **open indefinitely** while the device sits online looking healthy. **External pull-downs cannot help — the pin is actively driven.** **[V]** | **Catastrophic: unbounded flooding, invisible** | **The hardware deadman is mandatory, not optional.** Plus an `on_safe_mode:` hook writing raw GPIOs low via IDF calls. Consider `ESP_TASK_WDT_PANIC=n` (stage 1 then fires a *Core* reset at 2× timeout, which *does* clear GPIO) — but that costs the panic backtrace; prefer the deadman. *Benign note: the brownout path is a Core reset, so **power faults are already fail-closed**.* |
| **R1b** | **The deadman as originally specified would not have worked.** LEDC free-runs in hardware, so a hung loop, crash loop or safe mode leaves the square wave running and **the valve rail enabled**; and toggling from `loop()` instead is capped at ~31 Hz by `loop_interval_`, which the passive charge pump resolves to ~1.75 V — **below V<sub>GS(th)</sub>**, so the enable never asserts. **[V]** | **Catastrophic — the P0 mechanism silently absent** | Corrected: heartbeat from an **independent `esp_timer`** that checks a loop-liveness counter, driving a **retriggerable monostable (74HC123/CD4538)** rather than a passive charge pump. **Design corrected but not yet validated — E6 now requires proving it under a *deliberately hung* firmware, not by pulling power.** |
| **R2** | **`api:` and `wifi:` `reboot_timeout` both default to 15 min** — the stock config reboots the controller every quarter hour while HA or the AP is down. **[V]** | High — autonomy silently ceases; **this is the out-of-the-box behaviour** | `reboot_timeout: 0s` on both, then verify by pulling the AP's power mid-cycle. |
| **R3** | **Latching or position-holding valves chosen for cost.** They hold position with zero power, so a power cut mid-run leaves them **open with the controller dead** — precisely the danger being designed out. Making them safe needs an H-bridge per zone, a ~6800 µF reserve bank, an MCU-independent close-pulse supervisor, a charge interlock, **and a periodic self-test that actually discharges the bank** — because an electrolytic at 40 % capacitance still reads 22 V and still passes a naive check while no longer delivering the pulse. **[V]** | **Catastrophic; irreversible without re-plumbing** | Reject them. 24 VAC N/C solenoids only. *A purchasing decision made before any firmware exists.* |
| **R4** | **Cheap turbine flow sensor makes "leak detection" silently not work.** **[V]** | Medium — and **it is the default outcome** if you buy the obvious sensor | Volumetric meter, 1 L/pulse ([§10](09-water-metering.md)). |
| ~~**R5**~~ | ~~**Condensation inside a "waterproof" enclosure**~~ — **retired by D15.** The controller lives in a dry indoor technical room, so it does not thermally cycle into condensation. *Was ranked #4. Still applies to any outdoor valve box or the rain-gauge junction.* | — | — |
| **R6** | **Auto-resume after a crash-mid-run** turns one fault into a repeated one, and in a crash loop into an unbounded one. | Catastrophic | Abandon + re-evaluate; crash-loop brake; per-day per-zone volume budget as the real stop condition. |
| **R7** | **Volume-mode run with no time ceiling** — a dead meter produces an infinite run chasing a target that never arrives. | Catastrophic | Reject `VOLUME` with `duration == 0` at config validation; `MAX_RUN_MS`; meter-stuck detection. |
| **R8** | **`multiplier` ≤10 × `run_duration` ≤86400 s = a 240-hour run** expressible within the stock component's own limits. **[V]** | Catastrophic | Clamp both in YAML *and* against a compile-time ceiling in the guard. |
| **R9** | **Flash wear** — writing the total per turbine pulse destroys the flash in ~52 days. **[V]** | High; easy mistake | Write per litre or coarser; RTC_SLOW_MEM staging; FRAM; a CI grep gate. |
| **R10** | **Buried splice failure** — the leading cause of death for irrigation *wiring*. **D16 could eliminate this risk entirely** by siting the manifold in the technical room, leaving only pipe in the trench. | High over 10 years, **unless D16 removes it** | Manifold topology concentrates splices in one box; gel splices; spare cores; **current sensing detects the open circuit** — otherwise you find out when the plants die. |
| **R11** | **`utility_meter` defaults to `periodically_resetting: true`**, silently discarding water used during any HA gap. **[V]** | Medium — **it is the default** | Set `false`. |
| **R12** | **A stale HA input permanently suppresses irrigation** because "no data" was coded as "skip". | High — a dead garden caused by an HA integration breaking | P6: staleness timeouts default to the *permissive* value; nothing HA-sourced in the control path. |
| **R13** | **Alarm fatigue → the alarm system gets muted**, after which real faults are invisible. | High (social, not technical) | Only loss of control authority is CRITICAL; WARNING never locks out; a bounded diagnostic run so repairs don't require disabling anything. |
| **R14** | **DST double-fire or skip** at the Europe/Paris transitions. | **Certain, twice a year** | `(zone, schedule_id, local_date)` idempotency; reject windows inside 01:30–03:30; explicit tests. |
| **R15** | **DS3231 on the `ds1307` platform cannot report "I lost time"**, so a dead coin cell yields a plausible wrong time. **[V]** | Medium — watering at the wrong hour | Own sanity band + monotonicity check against a persisted last-known-good epoch. ⚠️ **Corrected:** the previously-suggested **PCF8563 fix does not work** — ESPHome's `pcf8563` driver also ignores the VL bit. The platform that genuinely reads the oscillator-stop flag, logs *"RTC halted, not syncing to system clock"* and refuses to sync is **`pcf85063`** **[V, read from ESPHome sources]**. A module is **€3.95 [V]**. |
| **R16** | **Untestable logic in YAML lambdas** — the path of least resistance. | High, indirectly: makes every other risk undetectable | Pure `lib/irrigation_core/` + a CI purity gate. |
| **R17** | **Becoming the sole maintainer of safety-critical firmware for a decade.** | Certain, given D2 | **Accepted deliberately.** Mitigated by: buying the *board* rather than designing one (removing ~40 h and all respin risk); keeping the logic in host-tested `lib/irrigation_core/`; and the reversibility argument — the firmware ports to any board with a YAML pin-map change. Note the alternatives are not maintenance-free either: `hydrawise` had **three breaking changes in 18 months**, `bhyve` **two Orbit API breaks in four months of 2026** **[V]**. |
| **R24** | **~130 entities sits in the zone where real ESP32 devices have failed to enumerate.** The failure is not memory but the **initial ListEntities dump**: verified reports of entities silently missing after connect (~250 entities → only 120–140 visible **[V]**), and a documented **task-watchdog reboot** from the loop spinning on a full TCP buffer. | Medium on old firmware; low on current | **Run ESPHome ≥ 2026.9**, which fixes the loop stall (#18577) and makes API OOM drop the connection rather than reboot (#18802/3). Treat the entity count as a budget. Fallback if it misbehaves: `update_interval: never` + staggered publishing. Note the pool controller currently runs **2026.7.2**, predating both fixes. |
| **R21** | **Time budget collapses mid-build.** A half-finished custom controller is **strictly worse than a bought one** — same risk profile *plus* untested code. | Medium over a season | The switch conditions in [§7](06-buy-vs-build.md#the-30-second-decision-rule) are pre-committed, not improvised: <80 h → OpenSprinkler + layer; <30 h → Rain Bird ESP-ME3 + layer. **Decide against the rule, not against sunk cost.** |
| ~~**R22**~~ | ~~**KinCony supply and documentation risk:**~~ **— retired 2026-09-05: no controller is being bought.** Original text kept for the decision record:  every B8/A8v3 variant currently shows **"Sold out"**, the vendor has **documented breaking pinout changes between revisions** (GPIO32/33 → 34/35, old pins silently repurposed), and **no B8 schematic is published anywhere**. **[V]** | Medium | Custom-lite is a fully-specified one-afternoon fallback. Mitigating fact: **KinCony's 71 ESPHome device pages are maintained upstream by the ESPHome project** (a PR as recent as 2026-09-03) **[V]**, so the configuration survives even if the vendor does not. |
| **R23** | **A non-latching max-runtime timer** faces a hung controller, re-arms every 45 min and waters **24× a day** — turning a safety device into a flood. | Low, but a subtle wiring mistake | Specify a **latching** timer requiring manual reset; wire the latch state to an HA binary sensor so the latch itself raises a CRITICAL. |
| ~~**R18**~~ | ~~Sizing the transformer from US 60 Hz datasheet figures — 50 Hz inrush is 28 % higher.~~ **Retired: the risk was real but the numbers were ours.** Hunter's 370 mA *is* the 50 Hz value; this document had applied the derate twice. See NFR-P2. | — | — |
| **R19** | **HomeKit exposure re-creates your previous pool outage** (which an Apple Home scene caused). | Medium | Explicitly exclude the hold switch and buttons from every HomeKit bridge. |
| **R20** | **OTA blocks the main loop and cannot be aborted**, so no run deadline is enforced during an update. | High if it happens mid-run | `ota: on_begin:` → shutdown; an HA-side `ota_safe` gate; the deadman. |

**The three that would keep me awake:** R1 (silicon behaviour no software can fix, invisible until it
floods), R2 (the default, and it silently negates the headline requirement), R3 (a purchasing decision
made before any code exists, irreversible without re-plumbing).
